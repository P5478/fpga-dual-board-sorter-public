# 07 · 性能与设计取舍

## 1. 关键指标

| 指标 | 数值 | 备注 |
|---|---|---|
| 摄像头 | 1280×720 | RAW10，60 fps |
| 链路帧率 | 30 fps | 相机隔帧发送 |
| 链路带宽 | 约 448 Mbit/s | 千兆的 45% |
| 单帧以太网包 | 1440 个 | 每行 2 段 |
| 识别目标 | 最多 8 个/帧 | 静态彩色模式 |
| 格子去抖 | 10 帧 ≈ 167 ms | 60fps 下 |
| 手势 | 1~5 指 | 像素流水线内完成 |
| 显示特效 | 19 档 | 含四宫格快照 |
| 单件分拣 | 约 20~26 秒 | 取决于落点距离 |

## 2. 时间都花在哪

一次分拣的时间几乎全部在机械臂动作上，视觉处理只占很小一部分：

```
识别与链路   ：毫秒级（每帧几十毫秒延迟，不影响节拍）
机械臂动作   ：20 步 × (运行时间 + 等待余量) ≈ 20 多秒
```

所以优化节拍的主要方向是缩短舵机运动和等待时间，
而不是识别算法——这也是为什么机械臂部分设计了"同组指令连发"和全局速度系数。

## 3. 主要设计取舍

| 取舍 | 选择 | 原因 |
|---|---|---|
| 帧率 | 30fps 而非 60fps | 60fps 要占 91% 带宽，MAC 无流控，风险太高 |
| 像素格式 | RGB565 而非 RGB888 | 带宽减半，人眼几乎看不出差别；下游特效按 RGB 设计，直接兼容 |
| 通信 | 裸 MAC 自定义帧 | 省资源、低延迟、可精确控制帧结构 |
| 标签传输 | 复用视频帧头 | 省一根线，天然每帧同步 |
| 去抖 | 连续 10 帧一致 | 折中：足够稳定，延迟可接受 |
| 机械臂控制 | 开环 + 回读校验 | 总线舵机自带位置闭环，上层只需保证指令不丢 |
| 双板分工 | 视觉 / 显控分离 | 避免采集-显示闭环，调试解耦 |

## 4. 已知限制

- **光照敏感**：静态颜色识别依赖颜色阈值，强光/色温变化大时需要重新标定；
- **遮挡**：目标互相遮挡时可能只识别到部分目标；
- **单臂串行**：机械臂一次只能搬一件，节拍受限于动作时间；
- **标定依赖现场**：格子位置和落点参数都是现场标定的，换场地需要重新校准。

## 5. 工程经验总结

1. **数据从源头取**。从显示链路取画面看起来省事，但会形成闭环，画面会"定格"。
2. **跨时钟域要成体系**。单比特用同步器，多比特用握手/双缓冲，别混用。
3. **协议要能自校验**。帧号 + 行号让接收端能发现断帧，比"看起来正常"可靠得多。
4. **调试接口要提前留**。串口状态行和数码管在定位问题时非常有用。
5. **参数要能现场改**。动作表、格子标定都设计成可重标定的，而不是写死。
6. **先保证不丢，再追求更快**。舵机指令丢失比慢一点严重得多。

## 6. 后续可以做的事

- 识别端加入更鲁棒的颜色空间（如 HSV）以抵抗光照变化；
- 机械臂加入基于视觉的落点微调，减少对接精度依赖；
- 支持多机械臂协同，提升吞吐；
- 显示端增加远程监控接口。
